# Step 01: Project Setup & Reproducibility

**Owner:** D · **Week:** 1 (Day 1) · **Effort:** 0.5 day · **Depends on:** none · **Feeds:** every step

## 1. Target

- A standalone git repo at `Desktop/QuantEdge/quantedge/`, pushed to a GitHub repository the judges can access.
- Python 3.12 virtual environment with pinned dependencies.
- `make setup`, `make pipeline`, `make run` and `make test` all work from a fresh clone.
- One configuration file (`config.yaml`) holds every tunable number. There are no "magic numbers" in code.

## 2. Why it matters

- Brief §7.1–7.2: "clean, documented, reproducible code", "runnable locally … with one command".
- Rubric: Software & interface quality (15%), which covers reproducibility from the submitted repo.
- **Environment fact:** `Desktop/QuantEdge` currently sits inside a git repo rooted at `C:\Users\PMIHIR` (remote `neurox-1-0/vendrai`). Committing there would leak this project into an unrelated repository.

## 3. How to achieve it

- `git init` a **new** repo inside `Desktop/QuantEdge/quantedge/`. The outer repo will see it only as an untracked folder; add `QuantEdge/` to the outer repo's `.git/info/exclude` so it is never picked up.
- Use Python **3.12** rather than the locally installed 3.14, because `arch`, `statsmodels` and `cvxpy` wheels are reliable on 3.12 and Streamlit Community Cloud supports it. Install with `py -3.12 -m venv .venv`, or `uv venv --python 3.12`.
- Install as an editable package (`pip install -e .`) so `from quantedge.risk import var` works in the app, the tests and notebooks alike.
- Pin exact versions in `requirements.txt` (generated by `pip freeze` after a successful test run).

## 6. Pitfalls

- Committing into the outer home-directory repo.
- Unpinned dependencies: yfinance and pandas change behaviour between versions.
- Hard-coded paths. Always resolve paths relative to the repo root (`Path(__file__).resolve().parents[n]`).
- Using Python 3.14 locally while the cloud runs another version, which produces numerical differences.

## 7. Defend it in Q&A

- *"How would we reproduce your numbers?"* Clone the repo and run `make setup && make run`. The data snapshot and seed are committed, so the numbers are byte-identical.
- *"Why Python 3.12?"* It has the most stable scientific wheels and matches the deployment target.
